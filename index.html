Component Library · Assignment

Building UI as reusable functions

Four components — Button, Card, Modal, Toast — each built as a plain JS factory function that takes a config object and returns a DOM node. No hardcoded copies: every instance on this page is the same function called with different props.

01 Button

createButton({ text, variant, size, onClick, disabled })

02 Card

createCard({ badge, badgeColor, title, description, footer })

03 Modal

openModal({ title, body, actions })

04 Toast

showToast({ message, type, duration })

05 Reflection

Thinking in components changed the shape of the code, not just its organization. In earlier tasks I wrote HTML/CSS/JS for exactly the layout in front of me — a button was three lines of markup with hand-typed classes, and if I needed a second one, I copy-pasted and tweaked it. Here, every visual piece is really just a function: I decide what varies (text, variant, onClick) and treat everything else as fixed style, so createButton() or createCard() gets called once and reused with different props instead of duplicated. It also forced me to separate "structure" from "content" — the component builds the DOM node and wiring, while the page just supplies data. The trade-off is I had to think upfront about the props each function needs, which took longer than hardcoding, but adding a fifth button or card afterward became a one-line call instead of editing HTML again.
